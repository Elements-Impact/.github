# GitHub Copilot Instructions for Elements Impact

This file provides global GitHub Copilot instructions for all Elements Impact repositories. These instructions guide AI-assisted development across the organization to ensure consistency, quality, and alignment with our standards.

## Organizational Context

- **Organization**: Elements Impact
- **Mission**: Driving sustainable technology solutions and environmental impact through innovative software development
- **Values**: Sustainability, Quality, Innovation, Collaboration, Transparency
- **Technical Focus**: Cloud-native applications, environmental data platforms, sustainability analytics, green technology solutions

## Instruction Hierarchy

In case of conflicting instructions, the following hierarchy applies:

1. Repository-specific `.copilot-instructions.md` (takes precedence)
2. This global organizational instruction file
3. Language and framework-specific best practices
4. General software development best practices

## General Principles

### Code Quality & Sustainability
- Write clean, maintainable, and efficient code that reduces computational waste
- Optimize for performance to minimize energy consumption
- Implement proper error handling and logging
- Follow SOLID principles and clean architecture patterns
- Consider the environmental impact of code decisions (e.g., algorithm efficiency, resource usage)

### Documentation & Collaboration
- Write clear, comprehensive documentation for all public APIs and complex logic
- Use descriptive variable and function names that convey intent
- Include meaningful commit messages following conventional commit standards
- Add comments for business logic, not obvious code
- Consider non-native English speakers in documentation

### Security & Privacy
- Follow security best practices for all code
- Never commit secrets, API keys, or sensitive information
- Implement proper input validation and sanitization
- Use secure coding practices appropriate for each language/framework
- Follow OWASP guidelines for web applications

## Language-Specific Guidelines

### Python
- Follow PEP 8 style guidelines
- Use type hints for all function parameters and return values
- Implement proper exception handling with specific exception types
- Use dataclasses for data structures
- Prefer pathlib over os.path for file operations
- Use virtual environments and requirements.txt/pyproject.toml for dependencies
- Write docstrings in Google or NumPy format
- Use pytest for testing with meaningful test names

### TypeScript/JavaScript
- Use strict TypeScript configuration
- Implement proper error boundaries in React applications
- Use functional components and hooks over class components
- Follow ESLint and Prettier configurations
- Use meaningful interface and type definitions
- Implement proper async/await error handling
- Use semantic versioning for packages
- Write unit tests with Jest/Vitest

### Infrastructure as Code
- Use Infrastructure as Code (Terraform, CloudFormation, etc.)
- Implement proper resource tagging for cost tracking and sustainability metrics
- Use least privilege principle for IAM roles and policies
- Implement proper backup and disaster recovery strategies
- Document infrastructure requirements and dependencies
- Use environment-specific configurations

### Docker & Containerization
- Use multi-stage builds to minimize image size
- Implement proper health checks
- Use non-root users in containers
- Optimize layers for caching and efficiency
- Use official base images when possible
- Document container requirements and environment variables

## Testing Standards

### General Testing
- Write tests before or alongside implementation (TDD/BDD)
- Aim for high test coverage (>80%) but prioritize meaningful tests
- Use descriptive test names that explain the scenario
- Implement unit, integration, and end-to-end tests as appropriate
- Use proper test data management and cleanup

### Test Structure
- Arrange-Act-Assert pattern for unit tests
- Mock external dependencies appropriately
- Test both happy paths and error conditions
- Include performance tests for critical paths
- Implement accessibility tests for user interfaces

## Environmental & Sustainability Focus

### Green Coding Practices
- Optimize algorithms for efficiency and reduced computational overhead
- Minimize unnecessary network requests and data transfers
- Implement caching strategies to reduce redundant operations
- Use efficient data structures and algorithms
- Consider carbon footprint in architectural decisions

### Monitoring & Metrics
- Implement monitoring for resource usage and performance
- Track sustainability metrics where applicable
- Use observability tools to identify optimization opportunities
- Monitor and alert on abnormal resource consumption

## AI/ML Specific Guidelines

### Model Development
- Implement proper data validation and preprocessing
- Use appropriate model evaluation metrics
- Implement model versioning and experiment tracking
- Consider model interpretability and explainability
- Implement proper feature engineering pipelines

### Data Management
- Implement proper data governance and privacy protection
- Use efficient data formats and compression
- Implement data validation and quality checks
- Consider data lineage and provenance tracking
- Implement proper data backup and archival strategies

## Git & Version Control

### Commit Standards
- Use conventional commit format: `type(scope): description`
- Types: feat, fix, docs, style, refactor, test, chore, ci, perf
- Keep commits atomic and focused
- Write meaningful commit messages that explain the "why"
- Reference issues and pull requests where applicable

### Branch Strategy
- Use feature branches for development
- Implement proper code review processes
- Use descriptive branch names: `feature/description`, `fix/issue-number`
- Keep branches up to date with main/master
- Delete merged branches promptly

## Code Review Guidelines

### Review Checklist
- Code follows established patterns and conventions
- Tests are comprehensive and meaningful
- Documentation is updated as needed
- Security considerations are addressed
- Performance implications are considered
- Environmental impact is minimized

### Review Feedback
- Provide constructive, specific feedback
- Suggest improvements rather than just pointing out problems
- Consider different perspectives and approaches
- Focus on code quality, not personal preferences
- Acknowledge good practices and improvements

## Deployment & Operations

### CI/CD Practices
- Implement automated testing in CI/CD pipelines
- Use proper environment promotion strategies
- Implement proper rollback mechanisms
- Use blue-green or canary deployments for critical services
- Monitor deployment success and application health

### Production Considerations
- Implement proper logging and monitoring
- Use appropriate alerting and notification strategies
- Implement proper backup and disaster recovery
- Consider scalability and performance requirements
- Plan for maintenance and updates

## Communication & Collaboration

### Issue Management
- Write clear, detailed issue descriptions
- Use appropriate issue templates
- Assign appropriate labels and milestones
- Reference related issues and pull requests
- Update issue status promptly

### Pull Request Standards
- Write clear, descriptive PR titles and descriptions
- Include testing instructions and screenshots where applicable
- Request appropriate reviewers
- Respond to feedback promptly and constructively
- Update documentation as needed

## Accessibility & Inclusivity

### Code Accessibility
- Follow WCAG guidelines for web applications
- Use semantic HTML and proper ARIA attributes
- Implement keyboard navigation support
- Consider screen reader compatibility
- Test with accessibility tools

### Inclusive Development
- Use inclusive language in code, comments, and documentation
- Consider diverse user needs and perspectives
- Implement internationalization support where applicable
- Consider different technical skill levels in documentation

## Learning & Improvement

### Continuous Learning
- Stay updated with industry best practices
- Participate in code reviews to learn from others
- Experiment with new technologies and approaches responsibly
- Share knowledge through documentation and team discussions
- Consider the learning curve for new team members

### Knowledge Sharing
- Document decisions and architectural choices
- Create runbooks and troubleshooting guides
- Share best practices and lessons learned
- Mentor junior developers and new team members
- Contribute to open source projects where appropriate
